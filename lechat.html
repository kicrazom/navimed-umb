Harness

leChatonFat4Navi: a local coding agent on the same two R9700 cards that carry the NaviMed benchmarks. No external API, no cloud: model, web search and tools all run on the workstation.

github.com/kicrazom/leChatonFat4Navi is a fork of leChatonFat by Mateusz Choiński (MIT licence). The original targets NVIDIA cards. The fork adds AMD support and keeps the NVIDIA path unchanged. It is a companion tool, not part of the benchmark envelope on the Results page.

What it runs

  • llama.cpp server with a GGUF model, OpenAI-compatible API on port 8001. Default model: Qwen3.6-35B-A3B-UD-Q4_K_XL.
  • SearXNG, a self-hosted metasearch engine, for web search without a third-party API.
  • MCP servers (Model Context Protocol, the standard way to plug tools into an agent): page fetch, SearXNG search, browser automation.
  • A generated opencode.json that connects the Opencode coding agent to all of the above.

What the fork changes

  • GPU_BACKEND=auto|nvidia|rocm|vulkan picks the llama.cpp image: server-cuda, server-rocm or server-vulkan.
  • Only the render nodes listed in AMD_GPU0 and AMD_GPU1 reach the container, so the integrated GPU stays out of the layer split.
  • make check_gpu prints the PCI ID of every render node, to tell discrete cards from the iGPU.
  • MODELS_DIR points at an existing GGUF directory; the default Hugging Face repository name is corrected.
  • Unsets TEMP (the sampling temperature) before start: with it set, llama-server on ROCm crashes while loading the model.

Measured on 2x Radeon AI PRO R9700

Single stream, one request at a time. Qwen3.6-35B-A3B-UD-Q4_K_XL, context 98,304 tokens, KV cache q4_0, flash attention, layer split 50/50. Prompt of 600 tokens, 256 generated tokens, prompt cache off, three runs, 2026-11-13.

In April 2026 this model did not start on these cards under vLLM 0.19 (a triton_kernels API mismatch, documented in the session log). llama.cpp does not use that code path.

On both models ROCm reads long prompts faster. Vulkan generates faster and its image is 25 times smaller. A coding agent re-reads a large context on every turn, so prompt processing usually decides.

Single machine, single model, N=3 per backend. Not a controlled benchmark in the sense of the Methodology page: no thermal gating, no power logging, two vLLM embedding services shared the first card during the runs.

Quick start on AMD

git clone https://github.com/kicrazom/leChatonFat4Navi
cd leChatonFat4Navi
make copy_env          # then edit .env:
                       #   GPU_BACKEND=rocm   (or vulkan)
                       #   AMD_GPU0=/dev/dri/renderD128
                       #   AMD_GPU1=/dev/dri/renderD129
                       #   TENSOR_SPLIT=50,50
                       #   MODELS_DIR=/path/to/gguf
make check_gpu         # which renderD is which card
make up
make smoke_test

Your user must be in the video and render groups.
