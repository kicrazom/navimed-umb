## paste-ready summary for the "Description" textarea

<p>NaviMed-UMB v0.4.0 widens the project from an internal engineering log into a reproducible release pipeline for open-weight large language models on consumer RDNA 4 hardware. Between-version, this release packages the closing of <strong>Run-3</strong> — the consumer-GPU surface of the PLLuM family — with two new public AWQ W4A16 checkpoints quantized locally on a single AMD Radeon AI PRO R9700 (32 GB, gfx1201): <a href="https://huggingface.co/mozarcik/Llama-PLLuM-8B-chat-2512-awq">Llama-PLLuM-8B-chat-2512-awq</a> (Llama 3.1 base, Llama 3.1 Community License with full <em>NOTICE</em>/<em>LICENSE</em>/<em>USE_POLICY.md</em> compliance) and <a href="https://huggingface.co/mozarcik/PLLuM-12B-chat-2512-awq">PLLuM-12B-chat-2512-awq</a> (Mistral-Nemo-Base-2407 derivative, Apache 2.0). Both are deployable on a single 32 GB consumer card under vLLM and complement the earlier v0.4.0 release of the Llama-PLLuM-70B family (eight model cards under <code>mozarcik/</code>).</p>

<p><strong>Engineering envelope (PUBLIC §11.1).</strong> Measurements on 1× R9700, TP=1, vLLM <code>0.19.0+rocm721</code>, <code>enforce_eager=True</code>, max_seq_len=2048: the 8B AWQ variant occupies <strong>5.53 GiB</strong> of weights leaving a <strong>22.22 GiB</strong> KV-cache budget and a maximum-concurrency envelope of <strong>88.89×</strong>; the 12B AWQ variant occupies <strong>8.03 GiB</strong>, leaving <strong>19.77 GiB</strong> KV and a <strong>63.27×</strong> envelope. Both are functional on entry-level workstation hardware (a single consumer-prosumer card), with the second R9700 free for a parallel sweep or co-located training.</p>

<p><strong>Gate 1 sanity evidence.</strong> Each variant passed 5/5 on a Polish-clinical sanity grid (factual prompt; clinical definitional, syndrome, instructional and procedural prompts) served via the <code>/v1/completions</code> endpoint with the chat template intentionally bypassed per the documented sanity-harness pattern. Raw JSON outputs are committed under <code>environment/sanity-tests/2026-05-26-*.json</code> in the GitHub source repository.</p>

<p><strong>Reproducibility.</strong> Both Run-3 quantizations share the same calibration corpus as the Run-2 70B family — <a href="https://huggingface.co/mozarcik/clinical-pl-smpc-awq-calibration">mozarcik/clinical-pl-smpc-awq-calibration</a>, <strong>418 fragments</strong> drawn from European-Medicines-Agency Summary-of-Product-Characteristics text (Polish, ~512 tokens each, No PHI) — so cross-variant quantization-quality comparisons across 8B / 12B / 70B are corpus-controlled. Quantization used <code>llm-compressor 0.10.0.2</code> with <code>device_map='auto'</code> across 2× R9700; the 12B AWQ pass completed in approximately <strong>25 minutes</strong> of walltime on local R9700 hardware.</p>

<p><strong>Failure-mode post-mortem (reusable by other operators).</strong> The overnight <code>hf download</code> library run stalled silently on shards 3-5 of the 12B BF16 source. The visible symptom downstream was a misleading <code>ImportError: protobuf</code> from the quant entry point; the actual root cause was the <code>hf_transfer</code> accelerated path truncating shards without raising, leaving the SentencePiece tokenizer assets incomplete and the load path falling through to the protobuf fallback. The rescue protocol — sequential <code>curl</code> against the Xet bridge (<code>cas-bridge.xethub.hf.co</code>) with IPv4 forced, one shard at a time, verified against the published shard sizes — is documented in the project logbook and is reusable by anyone hitting the same <code>huggingface_hub</code> failure on flaky-IPv6 networks.</p>

<p><strong>Public release surface (recap).</strong> v0.4.0 ships eight Llama-PLLuM-70B family AWQ checkpoints (base × {2412, 2508}; instruct × {2412, 2508, 2512}; chat × {2412, 2508, 2512}) plus the two Run-3 consumer-GPU variants above, all with dual-platform vLLM usage snippets (AMD ROCm validated; NVIDIA portable via <code>awq_marlin</code>), Gate 1 hardware envelope and Gate 2 coherence-probe evidence, and explicit "to the author's knowledge" first-public qualifiers.</p>

<p><strong>Paper roadmap.</strong> Paper #1 (engineering benchmark trade-offs, MDPI Electronics or IEEE Access target, Q1 2027 submission) has its Results-section outline locked in this release; Phase 2 throughput / latency / W-per-token measurements for Run-3 variants are scoped for v0.5.0.</p>

<p><strong>Embargo classification.</strong> This release ships PUBLIC §11.1 evidence only: engineering envelope, walltimes, thermal headroom, hardware configuration, methodology, model cards, license/notice/policy attribution, sanity evidence, and decision logs. Per-N throughput, latency distributions, KV cache occupancy curves, energy-per-token, and any cross-model comparative claim using concrete numbers remain EMBARGOED under METHODOLOGY §11.2 (and the stricter §11.3 for Polish-language models) pending peer-reviewed publication. Embargoed numerical results live in the gitignored <code>benchmarks/results/</code> tree on the workstation.</p>

<p><strong>Intended audience.</strong> Researchers preparing local AI infrastructure for privacy-sensitive workloads, hardware reviewers seeking reproducible methodology, and software maintainers working on RDNA 4 support in inference frameworks.</p>
