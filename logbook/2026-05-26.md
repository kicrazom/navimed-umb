## Failure mode notes (post-mortem)

### `hf download` stall on 12B shards 3-5 — root cause

The misleading symptom was a downstream `ImportError: protobuf` raised by the quant entry point, which prompted overnight orchestrator to mark `12B-chat-2512_quant: FAIL (3s)`. Actual root cause:

- `hf_transfer` accelerated mode silently truncated shards 3-5 (no error, no log, no `.incomplete` sentinel). Subsequent `tokenizer.model` / `tokenizer.json` load failed because the BF16 source dir was missing files; the load path went into the `sentencepiece` → `protobuf` fallback, surfacing the protobuf ImportError as the visible failure.
- Diagnosis path: directory listing on `~/models/PLLuM-12B-chat-2512/` showed missing files vs HuggingFace file tree → confirmed by `hf_hub_download(..., force_download=True)` reproducing the silent truncation → switched to direct `curl` against Xet bridge for deterministic per-shard pulls.

### Rescue protocol that worked

1. `curl -L --retry 5 -o <shard>.safetensors 'https://cas-bridge.xethub.hf.co/.../shard.safetensors'` — sequential, one shard at a time, IPv4-forced via `-4`.
2. Verified each shard against the HF-published `safetensors` size before proceeding to the next.
3. Re-ran `quant_llmc.py` — no protobuf error (because `tokenizer.json` was now intact), quant proceeded cleanly.

Lesson for `hf-download-watchdog`: byte-count alone is insufficient when `hf_transfer` mode is on. Add post-download tokenizer integrity check (or just switch to `HF_HUB_ENABLE_HF_TRANSFER=0` for tokenizer-heavy repos and let `huggingface_hub` do safe writes).

### Snap-Obsidian XDG_CACHE_HOME leak

Snap-installed Obsidian (the `snap/obsidian` confinement) overrides `XDG_CACHE_HOME` to its own snap-private path (`/home/$USER/snap/obsidian/...`). When `hf` CLI is invoked from a terminal session that inherited the snap environment (e.g. an integrated terminal launched from Obsidian, or any child process of the snap), `~/.cache/huggingface` resolves to the wrong path, and downloaded shards land inside the snap sandbox where they're invisible to subsequent shell sessions and to disk-usage tools.

Workaround (active): export `HF_HOME=$HOME/.cache/huggingface` explicitly in `scripts/_env.sh` (overrides XDG-derived default for `hf`/`huggingface_hub` regardless of how the parent shell was invoked).

Long-term: migrate Obsidian off snap to native `.deb` (tracked in vault memory `project_snap_obsidian_vaapi_fix` — same snap confinement was responsible for the VA-API leak earlier).
